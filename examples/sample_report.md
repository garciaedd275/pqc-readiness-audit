## Executive Summary

This report assesses network-facing TLS/certificate cryptography against
post-quantum risk. It does **not** test whether an attacker can break these
systems today — it tests whether the cryptography in use today will still
protect this traffic once a cryptographically relevant quantum computer
(CRQC) exists, and whether traffic captured today could be decrypted
retroactively ("harvest now, decrypt later").

- **128** distinct cryptographic configurations were observed across **6** scanned asset(s).
- **74** are classified **Vulnerable** (broken by Shor's algorithm on a CRQC, or already classically broken).
- **17** are classified **Weakened** (margin reduced by Grover's algorithm; not broken today).
- **29** are classified **Safe** and **0** are already **Post-Quantum**.
- **8** are **Unknown** — not recognized by the current rule table and need manual review.
- **43** internet-facing finding(s) involve a Shor-vulnerable key exchange — these are the ones "harvest now, decrypt later" applies to directly, because an eavesdropper recording that traffic today could decrypt it once a CRQC exists.
- **9** finding(s) are **Critical** priority and **47** are **High** priority; see the [Prioritized Remediation Roadmap](#prioritized-remediation-roadmap) below.

## Migration Timeline (NIST / CNSA 2.0 Anchors)

This assessment's urgency framing is anchored to public federal guidance,
not an arbitrary internal deadline:

- **Aug 2024** — NIST finalizes the first PQC standards: FIPS 203 (ML-KEM / Kyber, key encapsulation), FIPS 204 (ML-DSA / Dilithium, signatures), and FIPS 205 (SLH-DSA / SPHINCS+, signatures).
- **Nov 2024** — NIST IR 8547 (initial public draft) proposes deprecating ~112-bit-security classical algorithms (RSA-2048, ECC P-256/secp256r1) by 2030.
- **Jan 1, 2027** — CNSA 2.0: new National Security System equipment acquisitions are expected to be CNSA 2.0-compliant by default.
- **2030** — NIST target deprecation date for RSA-2048/ECC P-256-class algorithms. CNSA 2.0 target for exclusive use on software/firmware signing and networking equipment.
- **2033** — CNSA 2.0 target for exclusive use on web, cloud, and operating systems.
- **2035** — NIST target date after which RSA/ECC (at any key size) are disallowed. OMB M-26-15 sets this as the full-migration deadline for remaining federal systems, consistent with National Security Memorandum 10.

*Sources: NIST IR 8547 (Transition to Post-Quantum Cryptography Standards),
NSA CNSA 2.0 Transition Timeline (CSA, 2022, reaffirmed 2025), OMB M-26-15,
National Security Memorandum 10.*

## Scope & Methodology Notes

- **Scope:** network-facing TLS and X.509 certificate configuration only
  (this scan). Data-at-rest encryption, VPN/IPsec, SSH, code-signing, and
  HSM-embedded keys are out of scope for this report — see the README for
  the v2 roadmap.
- **Classification logic:** rule-based, not statistical — see
  `pqc_audit/rules.yaml` for the full, editable rule table and the
  cryptographic rationale behind each verdict.
- **Known detection limitation:** this scan reports the classical/hybrid
  key exchange actually negotiated by the scanning client. If a server
  only offers a PQC hybrid key exchange (e.g. X25519+ML-KEM) to clients
  that request it, and the scanning library doesn't request it, that
  server will show here as classical ECDHE even if it is already partially
  PQC-ready for compliant clients. Treat "no PQC key exchange observed" as
  "not confirmed," not "confirmed absent."
